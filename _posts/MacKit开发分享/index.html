MacKit 开发分享

原生 macOS 工具集 MacKit 开发分享

最近，我给自己的 Mac 写了一款小工具：MacKit。它使用 Swift 与 SwiftUI 构建，目前包含清洁模式、访达剪切、窗口预览、动态壁纸、灵动刘海和锁屏组件六个主要模块。

实际上，市面上已经有不少工具覆盖了这些能力。但有些应用体积大、功能复杂，有些常驻后台时占用资源较多，还有些交互路径不够顺手；更常见的情况是，同一种需求分散在不同软件里，为了几个小功能，便要同时维护多套设置。因此，我更关心一个具体的问题：那些每天使用电脑时都会遇到、单独拿出来又似乎不值得开发一款应用的小需求，能不能收进同一个轻量、顺手、原生，也最符合个人习惯的工具里？

恰好如今 AI 编程工具的能力越来越强。借助这些工具，只要能描述清楚需求，也可以从一个可运行的原型开始，逐步把一个想法落实到原生应用里。MacKit 也是在这样的过程中，从最初的几个小功能，慢慢发展成了现在更完整的桌面增强应用。

MacKit 项目地址

开发初衷：让 Mac 更符合自己的使用习惯

事实上，macOS 自带的交互已经足够完整，但完整并不代表每一个细节都恰好符合自己的使用习惯。

比如擦拭键盘和触控板时，稍微碰一下就可能触发输入；移动文件时，总会下意识地按下熟悉的剪切快捷键；打开多个窗口后，希望切换时能够先看见窗口内容；而程序坞上的应用图标，也让人自然地想知道它背后究竟开着哪些窗口。工作一段时间之后，又总想抬头看一眼播放中的歌曲、即将开始的日程、剩余电量，或者正在连接的外设。

这些操作没有复杂的业务流程，却会反复出现在日常使用中。虽然它们大多已有现成方案，但要么需要安装多个软件，要么需要在系统设置里完成一些不太直观的配置。于是我想，既然需求已经足够明确，不如把它们做成一个自己愿意常驻后台的小工具。

MacKit 的定位也由此确定：围绕我的个人使用习惯，逐步补充实用的系统交互。在「轻一点，顺手一点」的原则下，尽量减少对系统的侵入和资源占用，让这些不起眼的小功能真正融入日常使用。

基础工具：把高频操作改得更顺手

清洁模式：给键盘和屏幕一个干净的片刻

清洁模式的使用场景很简单：擦拭设备前，先暂时拦截键盘、鼠标和触控板输入，让清洁过程不再伴随意外点击和一串莫名其妙的字符。

进入后，内置显示器会显示黑色遮罩及退出提示，方便在擦拭屏幕时观察灰尘和污渍，其他屏幕则显示退出提示。这里最需要考虑的细节，应当是锁住输入之后如何退出。MacKit 采用连续按下并松开 5 次 Esc 的方式，每次按键都会更新退出进度。长按不会重复计数，相邻两次间隔超过 3 秒则从头开始，避免把一次无意间的触碰当成退出操作。

此外，系统休眠、当前会话失活、显示器配置变化或输入监听中断时，清洁模式都会自动退出。毕竟，这个功能只是想让擦拭设备更方便，输入能否安全恢复，同样应当被认真对待。

访达剪切：让熟悉的快捷键继续生效

在访达里移动文件，系统原本支持先复制，再通过 ⌘ ⌥ V 将项目移到当前位置。不过，对于习惯了 Windows 剪切逻辑的人来说，⌘ X、⌘ V 这组操作显然更加自然。

因此，MacKit 在访达的文件浏览区域提供了剪切操作：选中文件后按下 ⌘ X，再到目标位置按下 ⌘ V，即可请求访达移动文件；如果临时改变主意，按一下 Esc 就能取消待移动状态。

实现上，MacKit 会建立一个待移动会话，再将实际移动操作交给访达处理，因此同名文件冲突、移动过程以及撤销仍沿用系统的处理方式。剪贴板内容发生变化后，原有的待移动状态会自动失效，避免后续粘贴意外关联到旧文件。

窗口预览：先看见，再选择

当同一个应用打开多个窗口时，仅知道应用名称往往还不够。尤其在文档、浏览器或开发工具之间来回切换时，真正想找的是某一个窗口里的内容。

因此，MacKit 提供了类似 Windows 的窗口预览切换体验。使用系统快捷键 ⌘ Tab 切换窗口时，原本只显示应用图标的切换器会改为展示窗口缩略图；⌘ ` 则可以专门切换同一应用内的窗口。选择窗口时，可以通过方向键、Tab 或鼠标悬停操作，也可以按下 ⌘ Q、⌘ W、⌘ M 等快捷键，对选中的窗口执行退出、关闭或最小化操作。

窗口列表也需要照顾不同状态：最小化窗口排在普通窗口之后，无窗口的应用放在最后，确认选择后再打开应用。程序坞悬停预览和点击图标最小化也放在同一个功能页中，让键盘和鼠标两种使用习惯可以分别组合。

后来又加入了调度中心增强。在系统调度中心里，把指针移到某个窗口上，按下 ⌘ W 可以关闭它，按下 ⌘ Q 可以请求退出它所属的应用。为了避免误操作，这两个快捷键需要单独启用，关闭和退出仍沿用应用原生的处理流程；遇到未保存内容时，系统依然会弹出对应的保存提示。

动态壁纸：让本地视频成为桌面风景

与前面几项偏向操作效率的功能不同，动态壁纸更像是给每天面对的桌面留出一点个人空间。MacKit 支持一次导入多个本地视频，在应用内统一查看缩略图和文件名；确认素材可用后，再到「系统设置 → 墙纸 → MacKit-动态壁纸」中选择使用。导入的视频同样会出现在屏保选项中，桌面和锁屏可以分别指定。

素材会以副本的形式保存在 MacKit 的扩展目录中，管理列表中看到的也是这些副本，因此删除时不会影响原文件。素材较多时，可以使用“随机播放全部”，按照唤醒、登录或固定时间间隔进行轮播；锁屏也可以从导入的视频中选择独立素材，不再和桌面共用同一幅画面。过渡时长同样可以在应用内调整，让切换画面的节奏更柔和。

动态壁纸看起来只是一个视频播放器，实际却需要持续解码并交给系统绘制。如果只顾画面效果，很容易让一块静态桌面变成常驻后台的性能负担。因此，我加入了被遮挡时暂停的机制：当桌面剩余可见区域低于 10%，或切换到其他桌面时，视频就会停下；遮挡检测的频率也可以调整，在响应速度和检测开销之间做取舍。播放策略还会参考电池、设备温度、游戏模式和全屏应用状态，在条件允许时降低播放负担，必要时直接暂停。

需要说明的是，原生墙纸扩展需要 macOS 26 或更新版本，并且使用了系统尚未公开的接口。它目前的实现能够正常作为墙纸和屏保使用，但后续系统更新仍有可能改变相关行为。这也是整个项目中实验性最强的一部分。

桌面之外：让信息出现在需要的时候

灵动刘海：把频繁查看的信息移到屏幕顶部

MacBook 屏幕顶部的刘海原本是硬件结构留下的区域，但在 MacKit 中，它成了一个可以悬停展开、随手收起的常驻信息入口。这个功能参考了 Atoll 的相关实现，并重新整合进 MacKit 的应用生命周期和设置体系。

最常用的是媒体控制。系统正在播放歌曲时，灵动刘海可以显示专辑封面、歌曲信息和同步歌词，并支持播放暂停、切换歌曲、手动重新加载歌词以及选择输出设备。媒体面板处于暂停状态时，可以设置隔一段时间自动收回；临时想切歌，也可以在面板区域左右滑动，不必先把指针移回控制按钮。

除了媒体，它还承担了许多零散信息的查看入口：日历事件和提前提醒、暂存与分享文件的文件托盘、可以直接执行命令的交互式终端，以及相机、麦克风、录屏、大写锁定、专注模式、蓝牙、电池、音量、亮度等实时状态提示。这些功能并不是默认全部挤在同一处，而是按照设置和使用场景分别出现。

灵动刘海也针对不同显示器做了适配。它可以选择只在指定屏幕出现、自动跟随当前屏幕，或者同时显示在所有显示器上；内建显示器和外接显示器的闭合宽度、展开宽度、悬停延迟和暂停后面板的保留时间都可以调整。对于没有刘海的显示器，也可以选择隐藏到悬停时再出现。

锁屏组件：把锁屏从静态入口变成信息面板

如果说灵动刘海解决的是工作过程中的信息查看，那么锁屏组件更偏向“抬手看一眼”的场景。MacKit 在系统锁屏上加入了媒体、天气、电池、蓝牙设备、空气质量、日历和专注模式等可选组件，并按设置及可用数据决定是否显示。

天气组件可以切换温度单位、服务提供方和展示内容；电池组件可以显示充电状态与蓝牙设备电量；日历组件可以提醒即将开始的事件；媒体面板则延续了正在播放的歌曲和封面信息。所有组件都使用一套自定义液态玻璃样式，在不同桌面背景上尽量保持清晰，同时不显得突兀。

布局没有采用固定的一套模板。设置页会按照内建显示器的比例生成实时预览，用户可以在预览中上下拖动单个组件，调整它们在没有时间、日期和通知遮罩时的位置，也可以一键恢复默认布局。组件可以分别开关，这意味着锁屏最终展示什么，完全取决于自己更常看什么。

原生体验：从功能可用到轻量顺手

作为一个需要长期留在系统里的工具，MacKit 在交互设计和系统能力的使用上，都需要考虑对系统的侵入性与资源占用。比如清洁模式的输入拦截、访达剪切的文件移动请求、窗口缩略图的渲染、动态壁纸的视频解码，以及灵动刘海和锁屏组件的持续刷新，每一项都需要在原生体验和功能可用之间做权衡。

相比于围绕一个完整业务场景展开的应用，MacKit 更像是一份逐渐落实到代码里的个人使用习惯清单。清洁设备、移动文件、切换窗口，这些事情本身都很小，但因为每天都可能发生，改善其中一个细节也会带来持续的使用体验变化。动态壁纸、灵动刘海和锁屏组件，则让这款偏重操作效率的工具多了一点个人色彩。

MacKit 目前已经更新到 v0.11.4。后续功能会根据我的使用习惯逐步添加，同时继续打磨已有功能的稳定性、不同显示环境下的交互表现，以及动态壁纸与实时组件的资源占用。

如果你也想给自己的 Mac 补充这些操作，可以到 GitHub Releases 下载体验，将 DMG 中的 MacKit 拖入 Applications 即可安装。也欢迎到仓库提交 Issue，交流使用反馈和改进建议。
